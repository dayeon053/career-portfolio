# 슈어소프트테크 SW 설계 및 검증 지원 포트폴리오

C/C++ 코드의 빌드 조건을 분석하고, 요구사항을 규칙과 테스트로 구현해 온 신입 지원자입니다. 자동차 SW 설계 및 검증 직무에 맞춰 개인 역할과 확인 결과를 정리했습니다.

## 주요 역량

- 코드 분석: API와 컴파일 옵션, 의존성을 연결해 실행에 필요한 정보를 추출했습니다.
- 요구사항 구현: 결과뿐 아니라 조건 충족 여부와 누락 사유를 설명하는 규칙과 API를 만들었습니다.
- 검증 자동화: 반복 실행을 연결하고, 비교 기준과 남은 실패를 구분해 기록했습니다.

## 1. LogosFuzz - C/C++ 퍼징 하네스 생성에 빌드 조건 연결

**문제**  
LLM이 생성한 하네스를 실행하려면 API 이름뿐 아니라 헤더, 컴파일 옵션과 오류 반환 규약이 필요했습니다. Bazel 기반 분석을 다른 빌드 방식으로 넓히면서 기존 자동차용 규칙의 적용 범위도 구분해야 했습니다.

**개인 역할**  
4인 팀에서 API와 호출관계 추출, 제약 정보를 담는 지식베이스와 생성 단계 연결을 맡았습니다. 대상의 언어와 빌드 방식 등을 담는 프로필을 정의하고, CMake의 compile_commands.json에서 파일별 옵션을 가져오도록 구현했습니다. 기존 Bazel 경로를 유지하며 자동차 전용 오류 규칙은 해당 프로필에서 적용하도록 나누었습니다.

**검증 사례**  
libsndfile 1.2.2 평가에서 비교 기준이 되는 정답셋이 비어 있었습니다. 정답셋 생성 단계에 헤더 경로가 전달되지 않아 92개 파일 중 70개가 컴파일에 실패한 것이 원인이었습니다. 옵션 전달을 수정한 뒤 WSL에서 92개 파일의 컴파일을 확인하고, 선정 API 8개를 소스 라벨과 컴파일러 심볼로 각각 대조했습니다.

**확인 범위**  
2026년 10월 12일 기록 기준 전체 테스트는 1,142개 통과, 5개 건너뜀, 6개 실패였습니다. 실패는 변경 전 기준 브랜치에서도 확인해 이번 변경의 영향과 구분했습니다. API 비교 결과는 해당 버전과 환경의 8개 대상에 한정됩니다.

## 2. nodown - 판단 조건과 설명을 함께 반환하는 API

**문제**  
장기할부 거래에서 가맹점 폐업에 따른 검토 후보를 찾고 신청 준비를 돕는 서비스입니다. 최종 분류만 보여주면 어떤 조건이 충족되었는지, 정보가 부족한지 알기 어려웠습니다.

**개인 역할**  
4인 팀장으로 거래 탐지, 가맹점 상태 모의 조회, 사례 API와 기본요건 규칙 엔진을 맡았습니다. Python과 Flask로 요청 처리와 규칙 평가를 나누고, 판단 근거를 결과에 포함했습니다. 누락값은 추가자료 확인 상태로 처리했으며 가맹점 조회는 별도 인터페이스로 분리했습니다.

**검증 사례**  
정상 입력과 경계조건, 누락 입력을 단위 및 API 테스트로 확인했습니다. 합성 거래 12건에서 기본조건을 충족한 후보 7건과 그중 폐업 상태에 따른 알림 대상 4건을 확인했습니다. 

**확인 범위**  
합성 거래와 모의 조회를 사용한 프로토타입 검증입니다. 제도상 최종 판단은 기관 검토로 남기고, 구현한 규칙은 검토 후보와 근거를 제공하도록 설계했습니다.

## 3. SBOM/SCA - 저장소 입력부터 분석 결과까지 자동화

**문제**  
소스 의존성과 실행 서버의 분석이 나뉘어 있으면 각 결과가 어떤 구성요소를 가리키는지 함께 확인하기 어려웠습니다. 목록에 포함된 라이브러리와 실제 사용 여부도 구분해야 했습니다.

**개인 역할**  
화이트햇스쿨 6인 프로젝트에서 SBOM 생성 자동화와 CodeCommit 주소의 S3 전달을 주로 맡았습니다. Lambda, Systems Manager와 EC2를 연결했고, Amazon Inspector 실습과 Maven SBOM 명령, Package URL 조사는 보조 담당으로 수행했습니다.

**검증 사례**  
저장소 정보가 분석 단계로 전달되고 결과가 남는 흐름을 연결했습니다. 구성요소와 분석 결과를 대조하며, 팀은 저장소 입력, SBOM 생성, 서버 패키지 진단과 취약점 조회로 이어지는 시나리오를 시연했습니다.

**확인 범위**  
도구가 제시한 취약점 목록은 실제 사용 조건을 추가로 검토해야 하는 자료로 다뤘습니다.
